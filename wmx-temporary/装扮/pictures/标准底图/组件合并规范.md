# 组件合并规范

适用目录：`E:\微信开发者工具\Yummmmmmmi\wmx-temporary\displayment-wmx`

本规范用于约束宠物组件素材在进入最终合并流程前的尺寸、透明底、图层顺序与命名方式，避免后续拼合时出现错位、遮挡和命名不统一的问题。

当前内置生图流程更稳定的目标画布为 `1254x1254`。因此标准底图需要先从 `1024x1024` 扩展到 `1254x1254`，并且必须统一采用同一种补边规则，后续所有装扮组件也必须跟随这一规则，才能避免合并断层。

## 1. 图片基础规范

所有参与合并的组件图必须满足以下条件：

1. 画布尺寸一致，当前内置生图流统一为 `1254x1254`。
2. 文件必须为 `PNG`。
3. 非组件区域必须为透明底，不允许带棋盘底、白底、灰底或实色背景。
4. 组件在各自画布中的原始锚点位置不得被二次平移、缩放或旋转。
5. 标准底图从 `1024x1024` 扩展到 `1254x1254` 时，统一采用“主体整体居中，四边均匀补透明边”的方式。

扩展规则说明：

1. 原始 `1024x1024` 组件整体平移到 `1254x1254` 画布中心。
2. 左、上、右、下各新增 `115` 像素透明边。
3. 不允许某个组件单独采用不同的补边方向或偏移量。
4. 这样处理后，所有组件仍共享同一套相同的平移规则，重组时不会因为模板尺寸变化而互相错位。

2. `head_strawberry_ai_v1.png` 不得直接参与合并。
3. 标准组件应优先由 `expand_pet_components_1254.py` 自动生成，避免手工扩边产生偏移。

## 2. 合并图层规范

组件合并时，必须使用固定图层顺序，防止尾巴、躯干、头部和腿部互相压错。

推荐图层顺序：从下到上依次为

1. `tail`
2. `body`
3. `legs`
4. `head`

执行说明：

1. 尾巴放在最底层，因为当前整猫参考图中尾巴位于躯干后方。
2. 躯干放在尾巴上方，作为主体承接层。
3. 腿组件放在躯干上方，保证前后腿不会被躯干边缘遮住。
4. 头组件放在最上方，保证头部完整压住颈部连接处。

对“头、躯干、腿组件在图层最上方”的落地解释：

1. 可以理解为这三类组件都必须高于尾巴层。
2. 在三者内部仍按 `body -> legs -> head` 的顺序叠放，避免视觉冲突。

## 3. 文件命名规范

命名目标：将文件名中的“食物”字段与项目规范白名单对齐。

依据来源：

1. [README.md](E:/微信开发者工具/Yummmmmmmi/README.md)
2. [Project Specification.md](E:/微信开发者工具/Yummmmmmmi/Project%20Specification.md)
3. [js/data/foods.js](E:/微信开发者工具/Yummmmmmmi/js/data/foods.js)

项目规范要求：

1. 食物名必须使用项目白名单中的正式名称。
2. 不得自行使用同义词、缩写、近义替换或额外修饰词作为正式食物字段。

当前甜品白名单中，与本批素材最相关的正式名称是：

1. `奶油蛋糕`

因此，本目录当前文件名中的以下食物字段不建议继续使用：

1. `strawberry`
2. `shortcake`
3. `cream_decor`

原因：

1. 这些写法描述的是视觉风格或装饰形式，不是项目规范中的正式食物名。
2. `strawberry shortcake` 对应的中文语义更接近“草莓蛋糕”，但项目白名单并没有这个名称。
3. 当前最接近且合规的规范名是 `奶油蛋糕`。

## 4. 命名格式建议

建议统一采用以下格式：

`[component]_[canvas]_[food_name].png`

示例：

1. `head_1254_奶油蛋糕.png`
2. `legs_1254_奶油蛋糕.png`
3. `tail_1254_奶油蛋糕.png`

如果需要保留“这是装饰版而非原版”的语义，建议仅在食物名后追加统一状态字段：

`[component]_[canvas]_[food_name]_[variant].png`

建议可用的 `variant`：

1. `decor`
2. `styled`
3. `v2`

对应示例：

1. `head_1254_奶油蛋糕_decor.png`
2. `legs_1254_奶油蛋糕_decor.png`
3. `tail_1254_奶油蛋糕_decor.png`

不建议的格式：

1. `head_strawberry_ai_v1.png`
2. `head_1024_strawberry_shortcake.png`
3. `tail_1024_strawberry_cream_decor.png`

原因是它们没有把“食物字段”严格对齐到项目白名单。

## 5. 当前文件改名建议

在不改变原图内容的前提下，建议后续统一改为：

1. `head_1024_strawberry_shortcake.png` -> `head_1254_奶油蛋糕_decor.png`
2. `legs_1024_strawberry_shortcake.png` -> `legs_1254_奶油蛋糕_decor.png`
3. `tail_1024_strawberry_cream_decor.png` -> `tail_1254_奶油蛋糕_decor.png`

说明：

1. 上述是命名规范建议，本文件不自动重命名现有素材。
2. 在尾巴文件尚未修正为 `1024x1024` 透明底前，不建议直接纳入正式命名流。

## 6. 最终执行清单

正式合并前，逐项确认：

1. `head`、`body`、`legs`、`tail` 参与合并的版本全部为 `1254x1254`。
2. 四角像素 alpha 为 `0`，确认是透明底。
3. 尾巴层在最底，`body`、`legs`、`head` 依次向上。
4. 文件名中的食物字段统一使用项目规范白名单名称，本批建议统一为 `奶油蛋糕`。
5. 不使用 `ai_v1`、`strawberry`、`shortcake`、`cream_decor` 作为正式食物字段。
6. 所有组件都必须沿用同一套“主体整体居中，四边均匀留白”的 `1254` 扩展模板。
