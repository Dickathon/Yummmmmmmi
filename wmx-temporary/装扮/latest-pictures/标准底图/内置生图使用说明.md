# 内置生图使用说明

本文说明的是 Codex 对话里的内置生图能力，不是 PowerShell 里可以直接运行的公开命令，也不是项目里的 Python 脚本。

## 基本理解

内置生图的调用发生在 Codex 当前对话内部：

1. 在对话里发起生图请求。
2. Codex 后台生成图片。
3. 原始图片默认保存到 `C:\Users\27533\.codex\generated_images\...`。
4. 再把生成图复制到项目临时目录，进行去底、裁剪约束和校验。

普通终端里通常找不到稳定的 `image_gen.exe` 或 `codex image-gen` 入口，因为这个能力挂在当前 Codex 会话工具层里。

## 常用请求格式

生成尾巴组件时，可以按下面的约束描述：

```text
使用参考图 tail_1254.png。
只编辑尾巴组件。
保持 1254x1254。
使用纯 #00ff00 绿幕背景，方便后处理去底。
不要补全整猫。
不要移动尾巴锚点。
把当前食物主题转成服饰化尾巴装饰。
```

生成后的图片一般会落到类似路径：

```text
C:\Users\27533\.codex\generated_images\019e77ad-d0f9-7ed0-91a4-7a2353132870\ig_xxx.png
```

## 本项目处理流程

每张尾巴图的推荐流程：

1. 用内置生图生成候选图，要求纯绿色背景。
2. 复制候选图到 `E:\微信开发者工具\Yummmmmmmi\wmx-temporary\装扮\pictures\_tmp_tail_builtin`。
3. 用 `C:\Users\27533\.codex\skills\.system\imagegen\scripts\remove_chroma_key.py` 把绿色背景转成透明。
4. 用 `wmx-temporary\tools\clamp_component_to_reference.py` 把装饰限制回标准尾巴锚点区域。
5. 用 `wmx-temporary\tools\validate_component_offset.py` 校验尺寸、透明角、bbox 和尾巴覆盖率。
6. 通过后保存为 `E:\微信开发者工具\Yummmmmmmi\wmx-temporary\装扮\pictures\食物名_尾巴.png`。

## 和公开 OpenAI API 的区别

内置生图不需要在终端里提供 `OPENAI_API_KEY`，也不等于 `$env:IMAGE_GENERATION_API_KEY`。它只在 Codex 当前会话工具层可用。

公开 OpenAI API 是另一套调用方式，例如通过 `Invoke-RestMethod` 请求 `https://api.openai.com/v1/images/generations`，需要真实可用的 `OPENAI_API_KEY`。

简单区分：

- 内置生图工具：Codex 会话内可用。
- 公开 OpenAI API：终端或脚本可用，但需要 `OPENAI_API_KEY`。
- `generated_images` 目录：生成产物目录，不是接口。

## 继续生成

如果要继续批量生成，只需要在对话里说“继续”。Codex 会继续使用内置生图，并按上述流程处理到项目目录。
