# 项目规范（副本，以根目录 `Project Specification.md` 为准）

本项目用于抖音虚拟创作平台比赛作品开发，主要使用场景是手机端浏览和抖音 App 内 WebView 运行，不是电脑端网页。所有设计、布局、交互和性能取舍都必须优先考虑手机屏幕宽度、触摸操作、移动端性能和离线运行限制。

作品必须满足比赛对运行环境、网络能力和包体大小的限制，团队成员和 AI 工具在生成代码、资源和方案时都必须遵守以下规范。

## 1. AI 协作与改动边界规范

AI 工具必须严格按照本规范手册进行项目开发，不得脱离当前任务范围自行扩展需求、重构项目或修改无关代码。

- 默认按手机端 H5 作品进行设计和开发，不得优先采用电脑端网页思路、桌面端宽屏布局或依赖鼠标 hover 的交互。
- 只专注当前正在实现的功能，不得“顺手”修改其他成员的代码、无关文件、历史实现或项目结构。
- 不得主动修改主框架、工程配置、构建流程、公共入口、公共样式、公共工具函数等基础代码，除非当前任务明确要求。
- 不得为了个人偏好进行无关的格式化、重命名、抽象封装、目录调整、依赖替换或代码风格迁移。
- 如果确实需要修改共享代码或主框架代码，必须先说明修改原因、影响范围、潜在风险和替代方案，经团队确认后再执行。
- 每次提交或交付时必须写清楚说明，包括本次完成了什么、修改了哪些范围、是否影响其他功能、是否遵守离线运行和包体限制。
- AI 生成的代码应保持最小改动、目标明确、易于审查，避免把简单功能写成复杂架构。

## 2. 离线静态运行规范

作品必须是可离线运行的前端静态作品包，入口文件必须为根目录下的 `index.html`。

- 只允许使用 `HTML`、`CSS`、`JavaScript`、Canvas、WebGL、WASM、本地图片、本地音频、本地字体、本地视频、本地 JSON 等静态前端资源。
- 所有功能、交互、动画、状态、计分、关卡逻辑和计算逻辑都必须在前端本地完成。
- 禁止依赖任何后端服务、数据库、云函数、Serverless、远程接口或在线 AI API。
- 禁止使用 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource` 等任何网络通信能力。
- 禁止引用 CDN、远程脚本、远程字体、远程图片、远程音频、远程模型或其他外部资源。
- 禁止提交 `.apk`、`.exe`、`.app`、`.ipa`、后端程序或任何需要独立运行时的原生应用。
- 如果使用 Unity，只允许使用 Unity WebGL 导出的静态前端产物，不允许提交原生 Unity 可执行包。

AI 工具生成代码时，必须默认本项目处于完全断网环境，不能提出或实现任何需要服务器、接口、数据库或云端模型支持的方案。

## 3. 包体体积控制规范

作品最终上传包体必须小于 `8MB`。开发过程中应优先保证体积可控，建议将最终压缩包控制在 `7.5MB` 以内，预留平台压缩和元数据误差空间。

- 禁止引入大型框架、复杂依赖或无必要的第三方库。
- 禁止生成大量冗余代码、重复样式、未使用函数、未使用组件或过度抽象结构。
- 禁止加入未使用的图片、音频、字体、视频、模型、JSON 数据或调试文件。
- 禁止使用超大 Base64 内联资源，除非确认比独立文件更小且确有必要。
- 图片、音频、字体、视频等资源必须经过压缩后再放入作品包。
- 优先使用原生 `HTML`、`CSS`、`JavaScript`、Canvas 绘制、SVG、雪碧图和轻量资源实现效果。
- 当视觉效果、代码结构和包体体积发生冲突时，优先保证 `8MB` 包体限制和离线稳定运行。

AI 工具不得为了炫酷效果、通用架构或代码完整性生成明显增加包体的冗余内容。任何可能显著增加体积的方案，都必须先说明体积风险，再由团队确认是否采用。

## 4. 移动端视觉风格规范

本项目面向手机浏览的 H5/WebGL 作品，视觉设计必须移动端优先，并服务于离线运行和 `8MB` 包体限制。不得套用桌面端大屏布局、复杂网格或重素材设计。

- 设计基准宽度以 `375px` 为主，兼容 `360px` 到 `430px` 的常见手机视口；高度不写死，避免在不同 WebView 和安全区下溢出。
- 核心风格为日式极简、侘寂、和风现代，整体气质应宁静、克制、自然、质朴、温暖、有手工感。
- 页面采用单列布局，保留适度留白；卡片间距建议 `16px` 到 `20px`，区块间距建议 `40px` 到 `56px`。
- 主色调为深木棕 `#5C4B3A`，用于标题、主按钮和重点信息；背景色为暖 cream `#F5F0E8`；正文文字使用深灰 `#3D3D3D`；辅助文字使用暖褐 `#8B7355`。
- 辅助色使用浅橡木 `#C4A882` 和和纸白 `#E8DFD1`，用于边框、分割线、标签底色和背景过渡。
- 点缀色只在分类标签、局部强调和轻量渐变中使用：桜花粉 `#F4E1E1`、抹茶绿 `#8FBC8F`、竹青灰 `#9CAF88`。
- 卡片使用纯白或接近白色哑光底，圆角建议 `16px` 到 `20px`，边框为 `1px` 和纸白；阴影必须柔和克制，避免硬投影、霓虹光和彩色阴影。
- 按钮采用 pill 形圆角，主按钮为深木棕实心样式，次按钮为浅橡木线框样式；移动端交互以点击反馈为主，不依赖 hover 才能理解。
- 字体优先使用系统字体，不引入外部字体文件或在线字体；中文可使用苹方、思源黑体、微软雅黑或系统无衬线，字重保持轻而清晰。
- 背景可使用极淡纸质或亚麻纹理，但必须通过 CSS 或极小资源实现，透明度控制在 `3%` 到 `5%`，不得使用大图纹理。
- 食物图片和素材应使用柔和自然光、暖色调、极简摆盘和足够留白；不得为了风格效果加入大量高清大图。
- 动效保持慢、静、不打扰，只允许使用轻量的 `transform`、`opacity`、颜色和阴影过渡，时长建议 `0.3s` 到 `0.4s`。

AI 工具生成界面时，必须优先选择轻量实现。任何会显著增加资源体积、引入复杂动画、外部字体、大图背景或桌面端布局的方案，都必须先说明风险并等待确认。
