# 组件合并规范

适用目录：`wmx-temporary/displayment-wmx/`（仓库内相对路径）

本规范用于约束宠物组件素材在进入最终合并流程前的尺寸、透明底、图层顺序与命名方式，避免后续拼合时出现错位、遮挡和命名不统一的问题。

## 1. 图片基础规范

所有参与合并的组件图必须满足以下条件：

1. 画布尺寸一致，统一为 `1024x1024`。
2. 文件必须为 `PNG`。
3. 非组件区域必须为透明底，不允许带棋盘底、白底、灰底或实色背景。
4. 组件在各自画布中的原始锚点位置不得被二次平移、缩放或旋转。

当前目录检查结果：

| 文件名 | 尺寸 | 透明底 | 结果 |
| --- | --- | --- | --- |
| `head_1024.png` | `1024x1024` | 是 | 通过 |
| `head_1024_strawberry_shortcake.png` | `1024x1024` | 是 | 通过 |
| `body_1024.png` | `1024x1024` | 是 | 通过 |
| `legs_1024.png` | `1024x1024` | 是 | 通过 |
| `legs_1024_strawberry_shortcake.png` | `1024x1024` | 是 | 通过 |
| `tail_1024.png` | `1024x1024` | 是 | 通过 |

| `tail_1024_strawberry_cream_decor.png` | `1254x1254` | 否 | 不通过 |
| `head_strawberry_ai_v1.png` | `1024x1024` | 否 | 不通过 |

处理要求：

1. `tail_1024_strawberry_cream_decor.png` 不得直接参与合并，需先修正为 `1024x1024` 透明底版本。
2. `head_strawberry_ai_v1.png` 不得直接参与合并，当前可使用 `head_1024_strawberry_shortcake.png` 作为规范版本。

## 2. 合并图层规范

组件合并时，必须使用固定图层顺序，防止尾巴、躯干、头部和腿部互相压错。

推荐图层顺序：从下到上依次为

1. `tail`
2. `body`
3. `legs`
4. `head`

执行说明：

1. 尾巴放在最底层，因为当前整猫参考图中尾巴位于躯干后方。
2. 躯干放在尾巴上方，作为主体承接层。
3. 腿组件放在躯干上方，保证前后腿不会被躯干边缘遮住。
4. 头组件放在最上方，保证头部完整压住颈部连接处。

对“头、躯干、腿组件在图层最上方”的落地解释：

1. 可以理解为这三类组件都必须高于尾巴层。
2. 在三者内部仍按 `body -> legs -> head` 的顺序叠放，避免视觉冲突。

## 3. 文件命名规范

命名目标：将文件名中的“食物”字段与项目规范白名单对齐。

依据来源：

1. [Project Specification.md](../../Project%20Specification.md)
2. [js/data/foods.js](../../js/data/foods.js)

项目规范要求：

1. 食物名必须使用项目白名单中的正式名称。
2. 不得自行使用同义词、缩写、近义替换或额外修饰词作为正式食物字段。

当前甜品白名单中，与本批素材最相关的正式名称是：

1. `奶油蛋糕`

因此，本目录当前文件名中的以下食物字段不建议继续使用：

1. `strawberry`
2. `shortcake`
3. `cream_decor`

原因：

1. 这些写法描述的是视觉风格或装饰形式，不是项目规范中的正式食物名。
2. `strawberry shortcake` 对应的中文语义更接近“草莓蛋糕”，但项目白名单并没有这个名称。
3. 当前最接近且合规的规范名是 `奶油蛋糕`。

## 4. 命名格式建议

建议统一采用以下格式：

`[component]_[canvas]_[food_name].png`

示例：

1. `head_1024_奶油蛋糕.png`
2. `legs_1024_奶油蛋糕.png`
3. `tail_1024_奶油蛋糕.png`

如果需要保留“这是装饰版而非原版”的语义，建议仅在食物名后追加统一状态字段：

`[component]_[canvas]_[food_name]_[variant].png`

建议可用的 `variant`：

1. `decor`
2. `styled`
3. `v2`

对应示例：

1. `head_1024_奶油蛋糕_decor.png`
2. `legs_1024_奶油蛋糕_decor.png`
3. `tail_1024_奶油蛋糕_decor.png`

不建议的格式：

1. `head_strawberry_ai_v1.png`
2. `head_1024_strawberry_shortcake.png`
3. `tail_1024_strawberry_cream_decor.png`

原因是它们没有把“食物字段”严格对齐到项目白名单。

## 5. 当前文件改名建议

在不改变原图内容的前提下，建议后续统一改为：

1. `head_1024_strawberry_shortcake.png` -> `head_1024_奶油蛋糕_decor.png`
2. `legs_1024_strawberry_shortcake.png` -> `legs_1024_奶油蛋糕_decor.png`
3. `tail_1024_strawberry_cream_decor.png` -> `tail_1024_奶油蛋糕_decor.png`

说明：

1. 上述是命名规范建议，本文件不自动重命名现有素材。
2. 在尾巴文件尚未修正为 `1024x1024` 透明底前，不建议直接纳入正式命名流。

## 6. 最终执行清单

正式合并前，逐项确认：

1. `head`、`body`、`legs`、`tail` 参与合并的版本全部为 `1024x1024`。
2. 四角像素 alpha 为 `0`，确认是透明底。
3. 尾巴层在最底，`body`、`legs`、`head` 依次向上。
4. 文件名中的食物字段统一使用项目规范白名单名称，本批建议统一为 `奶油蛋糕`。
5. 不使用 `ai_v1`、`strawberry`、`shortcake`、`cream_decor` 作为正式食物字段。
